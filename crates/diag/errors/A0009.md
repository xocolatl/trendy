# A0009: missing attribute

A tuple value must have every attribute of its declared type, because a
tuple's type is its heading: the full set of attribute names and types.
There is no fix: only the program knows what value the attribute should
have, and a default the compiler chose, such as `0`, would compile and
compute with a value nobody gave. The help names what to add, and the note
gives its type.

```trendy,error
var point: tuple { x: approximate, y: approximate } := tuple { x: 1e0 };

operator main{} [];
```

The same rules hold for a call's arguments, which are a tuple of the
operator's parameters:

```trendy,error
operator greet{name: text, count: integer} [];

operator main{} [
    call greet{name: "Ada"};
];
```

An aggregate's `per` parameter, such as `sum`'s `of`, is computed for
each tuple of the relation. Projecting the relation on the attribute
instead would merge equal values, which would then count once, so a
projection on one attribute with no `per` argument is fixed to give the
whole relation and name the attribute as the argument:

```trendy,error
var harvests := relation {
    { region: "Punjab", crop: "wheat", tonnes: 950 },
    { region: "Punjab", crop: "rice", tonnes: 950 },
};
var total := sum{r: harvests{tonnes}};

operator main{} [];
```

Give every attribute a value:

```trendy
var point: tuple { x: approximate, y: approximate } := tuple { x: 1e0, y: 0e0 };
var harvests := relation {
    { region: "Punjab", crop: "wheat", tonnes: 950 },
    { region: "Punjab", crop: "rice", tonnes: 950 },
};
var total := sum{r: harvests, of: tonnes};

operator main{} [];
```
