# R0005: not exactly one tuple

`tuple from r` is the only tuple of the relation `r`, and `value from r`
the only value of its only tuple, so `r` must have exactly one tuple.
With none, there is no tuple to take; with several, no one of them is the
tuple meant.

When the relation is known while compiling, a wrong number of tuples is
reported there:

```trendy,error
var empty := relation { name: text } {};
var nobody := tuple from empty;

operator main{} [];
```

```trendy,error
var people := relation { { name: "Ada" }, { name: "Edgar" } };
var somebody := value from people;

operator main{} [];
```

When the relation is known only when the program runs, the program stops
instead, writing how many tuples it has to stderr, as in `error[R0005]: the
relation has 2 tuples, but exactly one is taken`, or `no tuples`, and
exiting with status 1, unless a transaction takes its error, a
`not_one_tuple { count }`.

Restrict the relation to the one tuple meant first, or project it on
attributes whose values all its tuples share:

```trendy
var people := relation { { name: "Ada", born: 1815 }, { name: "Edgar", born: 1923 } };
var ada := tuple from people where name = "Ada";
var born := value from (people where name = "Ada"){born};

operator main{} [];
```
