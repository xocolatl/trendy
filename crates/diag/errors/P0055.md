# P0055: a constraint written as another language writes it

A constraint is declared `constraint name := condition;`: a condition on
the unit's variables, which holds whenever a statement ends. `name := …`
defines its name, as for a variable, and the name says which constraint
is broken, when one is:

```trendy
var countries := relation { { country: "Kenya" } } key { country };
var official := relation { { language: "Swahili", country: "Kenya" } } key { language, country };

constraint known_countries := official{country} <= countries;

operator main{} [];
```

Tutorial D's `CONSTRAINT name condition`, without `:=`, a `:` where `:=`
goes, and SQL's `CREATE ASSERTION name CHECK (condition)` are fixed to
that, SQL's parentheses around the whole condition removed:

```trendy,error
var countries := relation { { country: "Kenya" } } key { country };
var official := relation { { language: "Swahili", country: "Kenya" } } key { language, country };

CONSTRAINT known_countries official{country} <= countries;
constraint known_languages: official{language} <= relation { { language: "Swahili" } };
CREATE ASSERTION some_language CHECK (count{r: official} > 0);

operator main{} [];
```

A constraint without a name, as a type's constraints are written, is
reported with help: what it is called is the program's to say.

```trendy,error
var countries := relation { { country: "Kenya" } } key { country };
var official := relation { { language: "Swahili", country: "Kenya" } } key { language, country };

constraint official{country} <= countries;

operator main{} [];
```
