# R0021: a program's own failure

`fail e` stops the program, writing the message of the error `e`, a value
of one of the subtypes of the prelude's type `error`, as its `message`
operator gives it. The prelude's `failure` says what a program writes in
its message; a program declares error subtypes of its own, each with its
`message`, to say what went wrong in its components. A `fail` fails when it
is computed, so one the compiler computes is reported when compiling, as a
call with arguments known then is:

```trendy,error
type no_conversion is error { { unit: text } };

operator message{error: no_conversion}: text [
    "no conversion from " || error.unit || " to grams"
];

operator grams{unit: text}: approximate [
    if unit = "kg" then 1000e0 else fail no_conversion{unit: unit}
];

var pinch := grams{unit: "pinch"};

operator main{} [];
```

A value that may be missing isn't a failure, but data: a relation, empty
when there is none, says so without one:

```trendy
heading conversion := { unit: text, grams: approximate };

var conversions: relation conversion := relation { { unit: "kg", grams: 1000e0 } };
var pinch := conversions where unit = "pinch";

operator main{} [];
```
