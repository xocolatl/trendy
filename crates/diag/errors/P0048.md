# P0048: a transaction started as SQL starts one

A transaction is a block, `transaction [ … ];`: its statements are undone,
all of them, if one fails, and kept, if none does, where its block ends.
SQL starts one with `BEGIN TRANSACTION` or `START TRANSACTION`, and ends it
with `COMMIT` later; in trendy the block is the transaction, so the word
before `transaction` is removed:

```trendy,error
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
    { granary: "Dhaka", sacks: 25 },
};

operator main{} [
    begin transaction [
        update stock { sacks := sacks - 10 } where granary = "Accra";
        update stock { sacks := sacks + 10 } where granary = "Dhaka";
    ];
];
```

Written as trendy writes it:

```trendy
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
    { granary: "Dhaka", sacks: 25 },
};

operator main{} [
    transaction [
        update stock { sacks := sacks - 10 } where granary = "Accra";
        update stock { sacks := sacks + 10 } where granary = "Dhaka";
    ];
];
```
