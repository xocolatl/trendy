# R0030: standard output that can't be written

`write` writes to standard output unless a call names another stream, and
the program stops if the system can't take what it writes: if standard
output is a file on a disk that fills up, or a device that fails, or if the
program was started with it closed. It writes the system's reason to stderr,
as in `error[R0030]: can't write standard output: No space left on device`,
and exits with status 1, as a failure to write a file does (R0026).

Standard output holds what a program writes, and gives it to the system all
at once, when it is full, before anything is written to standard error, and
as the program ends, or after each write on a terminal. So the write that
fails can be a later one than the write whose bytes the system didn't take,
or the program's end, after `main`'s last statement:

```trendy
uses { trendy.streams };

operator main{} [
    call write{line: "Nile"};
    call write{line: "Paraná"};
];
```

A pipe whose reader has stopped, as `head` does once it has its lines, is no
failure: the program ends there, quietly, as the system ends it.

Make room on the disk, or start the program with standard output open, as a
shell does unless told `>&-`.
