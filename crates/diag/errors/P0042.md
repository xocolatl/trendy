# P0042: Tutorial D's `ORDERED` or `ORDINAL`

A type's order compares its values by their components, in turn, each
after `asc` or `desc`, as a load's order compares tuples by their
attributes: `order [asc year, asc month, asc day]`, in the type's braces.
It names every component, so that values that differ are never equal in
it, and with it the type has `<`, `<=`, `>` and `>=`, and is of the kind
`ordered`, so `min`, `max` and a load's order take its values.

Tutorial D says a type is ordered with `ORDERED`, or `ORDINAL`, before
its possible representations, and has the program write its `<`
(*Type Inheritance and Relational Theory*, chapter 2). trendy writes
the order instead, which the compiler then follows, so it is always a
total order. Which components come first can't be told from the word, so
there is no fix:

```trendy,error
type day ORDINAL { { year: integer, month: integer, day: integer } };

operator main{} [];
```

```trendy,error
type day { { year: integer, month: integer, day: integer }, ordered };

operator main{} [];
```

List the components in the order they compare:

```trendy
type day {
    { year: integer, month: integer, day: integer },
    order [asc year, asc month, asc day],
};

operator main{} [];
```
