# A0063: an operator and its versions

Operators of one name and the same parameters' names are one operator:
the one whose parameters' types are supertypes of the others', its
specification, and versions of it, the others, each with parameters of
subtypes of those (*Type Inheritance and Relational Theory*, IM
Prescription 17). A call names the specification, and computes the most
specific version whose parameters its arguments' values are of, or else
the specification's own body. A specification can have no body, as an
operator of a union type's values, which its versions compute:

```trendy
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: ellipse}: integer [ 0 ];
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

A version is read-only exactly if its specification is, takes each
argument as it does, and has a result of its result's type or a subtype
of it. A `var` or `out` parameter has its specification's type, since the
operator can give the variable any value of it:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: ellipse}: text [ "none" ];
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

A specification without a body needs a version for each type a value can
be of, which is reported at that type, since the program that adds a
subtype to a union type adds its versions:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

And an operator without a body and without versions computes nothing.
