# A0063: an operator and its versions

Operators of one name and the same parameters' names are one operator:
the one whose parameters' types are supertypes of the others', its
specification, and versions of it, the others, each with parameters of
subtypes of those (*Type Inheritance and Relational Theory*, IM
Prescription 17). A call names the specification, and computes the most
specific version whose parameters its arguments' values are of, or else
the specification's own body. A specification can have no body, as an
operator of a union type's values, which its versions compute:

```trendy
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: ellipse}: integer [ 0 ];
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

A version is read-only exactly if its specification is, takes each
argument as it does, and has a result of its result's type or a subtype
of it. A `var` or `out` parameter has its specification's type, since the
operator can give the variable any value of it:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: ellipse}: text [ "none" ];
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

A specification without a body needs a version for each type a value can
be of, which is reported at that type, since the program that adds a
subtype to a union type adds its versions:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator sides{f: plane_figure}: integer;
operator sides{f: polygon}: integer [ f.corners ];

operator main{} [];
```

A version can be for tuples, relations or arrays of subtypes. A tuple is
of a tuple type if each attribute's value is of its type, and a relation
or an array if each tuple or element is (IM Prescription 27), so an empty
one is of every relation or array type of its heading or elements. Two
versions for relations or arrays of disjoint types are then both for an
empty one, and no version can be more specific than both, since no type
written in trendy is a type of the empty one alone:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator kinds{r: relation { f: plane_figure }}: text [ "figures" ];
operator kinds{r: relation { f: ellipse }}: text [ "ellipses" ];
operator kinds{r: relation { f: polygon }}: text [ "polygons" ];

operator main{} [];
```

And an operator without a body and without versions computes nothing.

A unit gives versions of the specifications it sees, another unit's
among them, so the versions of one specification can be in several
units, and each combination of subtypes has exactly one over the program.
As the units are in no order, versions of one combination in several
units are each reported, naming the others. For the units
`figures.trendy` and `discs.trendy`:

```trendy,unit figures
interface

type figure union;

type square is figure { { side: approximate } };

type disc is figure { { r: approximate } };

operator area{f: figure}: approximate;

implementation

operator area{f: square}: approximate [ f.side * f.side ];
```

```trendy,unit discs
uses { figures };

operator area{f: disc}: approximate [ 3e0 * f.r * f.r ];
```

```trendy,error
uses { figures };

operator area{f: disc}: approximate [ 3.14e0 * f.r * f.r ];

operator main{} [];
```
