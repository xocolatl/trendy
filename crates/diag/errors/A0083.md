# A0083: a constraint on another unit's variables

A constraint is a condition on its unit's own variables (TTM RM
Prescription 23). Other units read and assign the variables a unit's
interface declares, so the constraints on those are in the interface
too, where every unit that assigns them sees what can fail its
statements. A constraint that one unit declared on another's variables
would fail that unit's own statements by a condition it never sees, as
a unit never sees the units that use it. So it is an error, at the
constraint's name. For the unit `lakes/depths.trendy`:

```trendy,unit lakes.depths
interface

heading lake := { name: text, depth: integer };

var known: relation lake key { name };
```

```trendy,error
uses { lakes.depths };

constraint deep := is_empty{r: known where depth <= 0};

operator main{} [];
```

The constraint belongs in the interface of the unit whose variables it
is on:

```trendy,unit lakes.depths
interface

heading lake := { name: text, depth: integer };

var known: relation lake key { name };

constraint deep := is_empty{r: known where depth <= 0};
```

```trendy
uses { lakes.depths };

operator main{} [
    insert known relation { { name: "Baikal", depth: 1642 } };
];
```

A constraint that relates one unit's variables to another's, as this one
keeps the lakes visited among those known, belongs to neither, so the
variables it relates go in one unit, whose constraint it then is:

```trendy,error
uses { lakes.depths };

var visited: relation { name: text } key { name };

constraint visited_known := visited <= known{name};

operator main{} [];
```
