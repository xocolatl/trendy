# A0054: an `out` parameter read before it is assigned, or not assigned

An `out` parameter takes a variable, as a `var` one does, whose value
before the call is never read: the operator assigns the parameter before
it reads it, and assigns it on every path, whichever way its `if`s and
loops go, so that the variable always has a value the operator gave it.

So reading an `out` parameter before it is assigned on every path to the
read is an error, as is a change to it that reads it, such as `insert`,
or passing it to a `var` parameter:

```trendy,error
operator count_up{out n: integer} [
    var start := n;
    n := start + 1;
];

operator main{} [];
```

And so is an operator that may end without assigning one: an `if`
without `else`, a `while` loop and a `for` loop may not run their
statements, so what only they assign isn't assigned on every path.

```trendy,error
operator sign{x: integer, out s: text} [
    if x < 0 then [
        s := "negative";
    ];
];

operator main{} [];
```

Assign it first, on every path, and read it after; or make it `var`, to
read the value of the variable it is passed:

```trendy
operator count_up{var n: integer} [
    var start := n;
    n := start + 1;
];

operator sign{x: integer, out s: text} [
    if x < 0 then [
        s := "negative";
    ] else [
        s := "not negative";
    ];
    call debug_value{v: s};
];

operator main{} [];
```
