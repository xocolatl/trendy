# P0051: a warning written as another language writes it

A program warns with `warn e;`, where `e` is an error, a value of one of
the prelude's type `error`'s subtypes, which says what is worth knowing,
and carries on. The innermost transaction with `collecting` running
collects it, beside the errors it fails with, or else the program writes
its message:

```trendy
type running_low is error { { city: text, sacks: integer } };

operator message{error: running_low}: text [
    error.city || " has " || to_text{from: error.sacks} || " sacks left"
];

operator take{city: text, sacks: integer} [
    if sacks < 10 then [
        warn running_low{city: city, sacks: sacks};
    ];
    warn failure{message: "took from " || city};
];

operator main{} [];
```

PL/pgSQL's `RAISE WARNING` and `RAISE NOTICE`, and a call of another
language's operator that warns, as JavaScript's `console.warn(…)` and
Python's `warnings.warn(…)` and `logging.warning(…)`, are fixed to it.
PL/pgSQL's `RAISE EXCEPTION`, which fails, is fixed to `fail` (P0047).

```trendy,error
type running_low is error { { city: text, sacks: integer } };

operator message{error: running_low}: text [
    error.city || " has " || to_text{from: error.sacks} || " sacks left"
];

operator take{city: text, sacks: integer} [
    if sacks < 10 then [
        RAISE WARNING running_low{city: city, sacks: sacks};
    ];
    console.warn(failure{message: "took from " || city});
];

operator main{} [];
```

A warning's message comes from its error, as a failure's does, so a
format string and its arguments, as `RAISE WARNING 'low: %', city`
writes them, are the error's components, and its `message` puts them
together.
