# R0014: a text isn't a value of the type

`parse_integer`, `parse_approximate` and `parse_boolean` read a value
from text, and have no value for a text that doesn't write one of their
type, or writes a number out of its type's range.

- `parse_integer` reads an integer as trendy writes one: decimal digits,
  with a `-` before them if it is negative, and nothing else, so not
  `+5`, `1_000`, `0x1F` or `4.5`, and not ` 42`, with a space. Integers
  are 64-bit signed, from -9223372036854775808 to 9223372036854775807.
- `parse_approximate` reads a decimal number: digits, then a `.` and more
  digits if it has a fraction, then an exponent if it has one, `e` or
  `E`, an optional sign and digits, all with a `-` before them if it is
  negative. So it reads `2.5`, `6650` and `1.5e-3`, but not `.5`, `5.`,
  `1,5`, `inf` or `NaN`. Approximate numbers are finite, up to about
  1.8e308 in magnitude; a number too small to tell from zero is zero.
- `parse_boolean` reads `true`, `t`, `yes`, `y` or `1` as true, and
  `false`, `f`, `no`, `n` or `0` as false, in any case, and nothing else,
  so not ` yes`, with a space, nor `on`. To read a boolean written
  otherwise, compare the text with the one for true: `answer = "on"`.

When the text is known while compiling, the failure is reported there:

```trendy,error
var n := parse_integer{from: "4.5"};

operator main{} [];
```

```trendy,error
var x := parse_approximate{from: "1e400"};

operator main{} [];
```

```trendy,error
var b := parse_boolean{from: "on"};

operator main{} [];
```

When the text is known only when the program runs, as a file's is, the
program stops at the call instead, writing the text and the type to
stderr, as in `error[R0014]: "4.5" isn't an integer`, and exits with
status 1. `load_csv` reads each field of a CSV file as its attribute's
type, as these operators read them, and stops so for one that isn't,
writing its column, with the header's name for it if the file has one,
its line and its attribute too, as in `error[R0014]: "4,5", in column 4
("area") on line 3 of "cities.csv", isn't an approximate number, the
type of `km2``. Without a header, a field of the first record that isn't
its attribute's type may be a header's, which `header: true` skips, and
the error says so.

Read each value with the operator of its type, from text that writes
only the value:

```trendy
var n := parse_integer{from: "-42"};
var x := parse_approximate{from: "4.5"};
var b := parse_boolean{from: "Yes"};
var on := "on" = "on";

operator main{} [];
```
