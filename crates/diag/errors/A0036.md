# A0036: a constraint that checks itself

An operator can call itself (see [Recursion](#recursion) in the language
reference), as whatever it decides can stop it. Checking a constraint is
another matter, as it runs before anything can decide: a type's constraint can't
select a value of its type, as every selection checks the constraints, and
neither can a conversion between a type's possible representations, which a
selection in that representation makes, or a constraint in an operator's braces
call the operator. Each would check itself again, whatever its value would be.
And writing an error can't lead back to the `fail` that made it. The error names
what is in the cycle, with a label at each call.

A type's constraints are checked whenever a value of it is selected, by
its selector, `replace` or `update`, so a constraint that selects one,
directly or through operators, is a cycle:

```trendy,error
type fraction {
    { numerator: integer, denominator: integer },
    constraint fraction{numerator: numerator, denominator: denominator} <> fraction{numerator: 0, denominator: 0},
};

operator main{} [];
```

So is a possible representation's own constraint that selects a value in
that representation, which checks it of the components given:

```trendy,error
type tens {
    { n: integer },
    { big: integer, constraint tens{big: big - 10}.n >= 0 }
        to { n := big div 10 }
        from { big := n * 10 },
};

operator main{} [];
```

Compute a constraint from the components alone:

```trendy
type fraction {
    { numerator: integer, denominator: integer },
    constraint denominator <> 0,
};

type tens {
    { n: integer },
    { big: integer, constraint big >= 10 }
        to { n := big div 10 }
        from { big := n * 10 },
};

operator main{} [];
```

A constraint in an operator's braces is checked at every call of it, so one
that calls the operator, directly or through others, would check itself again:

```trendy,error
operator positive{n: integer, constraint positive{n: n} > 0}: integer [
    n
];

operator main{} [];
```

Compute it from the parameters alone:

```trendy
operator positive{n: integer, constraint n > 0}: integer [
    n
];

operator main{} [];
```

An error that nothing takes is written with `message`, and one that `message`
fails with is written in its turn, so a `fail` that writing its error can reach
could go on writing errors without end, which no stack limit would stop:

```trendy,error
type refused is error { { code: integer } };

operator checked{n: integer}: integer [
    if n < 0 then fail refused{code: n} else n
];

operator message{error: refused}: text [
    to_text{from: checked{n: error.code}}
];

operator main{} [];
```

Compute the message from the error's components:

```trendy
type refused is error { { code: integer } };

operator checked{n: integer}: integer [
    if n < 0 then fail refused{code: n} else n
];

operator message{error: refused}: text [
    "refused: " || to_text{from: error.code}
];

operator main{} [];
```
