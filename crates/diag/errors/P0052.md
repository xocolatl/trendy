# P0052: a unit written as another language writes it

A file is a unit, named by its path from the program's root, the
directory of `main`'s file: `lakes/depths.trendy` is the unit
`lakes.depths`. Nothing in the file names it. `interface` starts the
declarations other units see, and `implementation` those they don't,
each up to the next, and the unit ends where its file does:

```trendy
interface

operator deepest{depths: relation { m: integer }}: integer;

implementation

operator deepest{depths: relation { m: integer }}: integer [
    max{r: depths, of: m}
];

operator main{} [];
```

Delphi's and Pascal's `unit lakes;`, `program lakes;` and `library
lakes;`, Modula-2's `MODULE lakes;`, Haskell's `module Lakes where`, and
Java's and Go's `package lakes`, which name the unit, are removed, as is
Delphi's `end.`, and C++'s `public:` and `private:` labels are fixed to
the headers:

```trendy,error
unit lakes;

public:

operator deepest{depths: relation { m: integer }}: integer;

private:

operator deepest{depths: relation { m: integer }}: integer [
    max{r: depths, of: m}
];

operator main{} [];

end.
```

A word that marks a declaration exported, Rust's `pub`, JavaScript's
`export` or Java's `public`, is reported with help, as what the
interface declares is what a unit exports, and moving a declaration
there, with its body after `implementation`, is the program's to do:

```trendy,error
pub operator deepest{depths: relation { m: integer }}: integer [
    max{r: depths, of: m}
];

operator main{} [];
```

A unit has no `initialization` or `finalization` section: nothing runs
as a program starts but `main`, and a variable's initial value is
computed when compiling.

```trendy,error
var total: integer;

initialization
    total := 0;

operator main{} [];
```
