# A0085: what never runs

A `return`, a `leave`, an `iterate` and a `fail` leave the block they are
in, and so does an `if` whose branches all do: nothing after them in the
block runs. Statements there are an error, which the fix deletes, as
running them would need another way to the block:

```trendy,error
operator report{n: integer} [
    if n < 0 then [
        call debug_value{v: "negative"};
        return;
    ] else [
        call debug_value{v: "not negative"};
        return;
    ];
    call debug_value{v: n};
];

operator main{} [];
```

```trendy,error
operator first_over{a: array integer, limit: integer} [
    for n in a loop [
        if n > limit then [
            call debug_value{v: n};
            leave;
            call debug_value{v: "found"};
        ];
    ];
];

operator main{} [];
```

So is a value after a statement that always leaves a read-only operator's
body, or a value block, which is never computed. The fix makes the value a
`return` just before it gives the body's; after an `if` whose branches all
leave, the body's value is written with an `if` expression, or `fail e`,
which choose it:

```trendy,error
operator double{x: integer}: integer [
    return x * 2;
    x + x
];

operator main{} [];
```

What a block is to run after it leaves goes before it leaves:

```trendy
operator report{n: integer} [
    if n < 0 then [
        call debug_value{v: "negative"};
    ] else [
        call debug_value{v: "not negative"};
    ];
    call debug_value{v: n};
];

operator first_over{a: array integer, limit: integer} [
    for n in a loop [
        if n > limit then [
            call debug_value{v: n};
            call debug_value{v: "found"};
            leave;
        ];
    ];
];

operator double{x: integer}: integer [
    x * 2
];

operator main{} [];
```
