# P0027: type parameter written another way

An operator's type parameters are declared after its parameters and
result type, with `types`, each as `any type`, `any tuple` or
`any relation`. Each call gives them types from its arguments, so a call
never names them. Rust, TypeScript, Java and C++ write them in angle
brackets after the name instead, and the fix moves them to `types`:

```trendy,error
operator same<T>{a: T, b: T}: boolean [
    return a = b;
];

operator main{} [];
```

```trendy
operator same{a: T, b: T}: boolean
    types { T: any type }
[
    return a = b;
];

operator main{} [];
```

A parameter of a kind of type that is only used once needs no name:
`any tuple` and `any relation` are written that way round, not
`tuple any` or `relation any`.

```trendy,error
operator show{r: relation any} [
    call debug_value{v: r};
];

operator main{} [];
```

```trendy
operator show{r: any relation} [
    call debug_value{v: r};
];

operator main{} [];
```
