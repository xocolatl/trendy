# P0047: a failure written as another language writes it

A program fails on purpose with `fail e`, where `e` is an error, a value
of one of the prelude's type `error`'s subtypes, which says what went
wrong. As a statement, it is `fail e;`:

```trendy
type no_conversion is error { { unit: text } };

operator message{error: no_conversion}: text [
    "no conversion from " || error.unit || " to grams"
];

operator grams{unit: text}: approximate [
    if unit = "kg" then 1000e0 else fail no_conversion{unit: unit}
];

operator weigh{unit: text} [
    if grams{unit: unit} < 1e0 then [
        fail failure{message: unit || " is lighter than a gram"};
    ];
];

operator main{} [];
```

Java's, JavaScript's and C++'s `throw`, Python's and Ruby's `raise`, and
PL/pgSQL's `RAISE EXCEPTION` are fixed to it; PL/pgSQL's `RAISE WARNING`
and `RAISE NOTICE`, which carry on, are fixed to `warn` (P0051):

```trendy,error
type no_conversion is error { { unit: text } };

operator message{error: no_conversion}: text [
    "no conversion from " || error.unit || " to grams"
];

operator grams{unit: text}: approximate [
    if unit = "kg" then 1000e0 else throw no_conversion{unit: unit}
];

operator weigh{unit: text} [
    if grams{unit: unit} < 1e0 then [
        raise failure{message: unit || " is lighter than a gram"};
    ];
    if grams{unit: unit} > 1e6 then [
        RAISE EXCEPTION failure{message: unit || " is heavier than a tonne"};
    ];
];

operator main{} [];
```

A `fail` gives the error it fails with. Another language's `throw;` and
Python's bare `raise` fail again with the exception being handled, but
nothing in trendy is: a failure a transaction collects is a value, in
the variable `collecting` adds it to, and one it doesn't collect goes on
by itself. So `fail;` alone is reported, with no fix, since only the
program knows what went wrong:

```trendy,error
operator main{} [
    var found: relation transaction_collection;
    transaction collecting found [
        fail;
    ];
];
```

To let a transaction's failure go on, to the transaction around it, or
the program's end, leave out its `collecting`:

```trendy
operator main{} [
    transaction [
        fail failure{message: "nothing to move"};
    ];
];
```
