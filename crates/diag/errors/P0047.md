# P0047: a failure written as another language writes it

A program fails on purpose with `fail e`, where `e` is an error, a value
of one of the prelude's type `error`'s subtypes, which says what went
wrong. As a statement, it is `fail e;`:

```trendy
type no_conversion is error { { unit: text } };

operator message{error: no_conversion}: text [
    "no conversion from " || error.unit || " to grams"
];

operator grams{unit: text}: approximate [
    if unit = "kg" then 1000e0 else fail no_conversion{unit: unit}
];

operator weigh{unit: text} [
    if grams{unit: unit} < 1e0 then [
        fail failure{message: unit || " is lighter than a gram"};
    ];
];

operator main{} [];
```

Java's, JavaScript's and C++'s `throw` and Python's and Ruby's `raise`
are fixed to it:

```trendy,error
type no_conversion is error { { unit: text } };

operator message{error: no_conversion}: text [
    "no conversion from " || error.unit || " to grams"
];

operator grams{unit: text}: approximate [
    if unit = "kg" then 1000e0 else throw no_conversion{unit: unit}
];

operator weigh{unit: text} [
    if grams{unit: unit} < 1e0 then [
        raise failure{message: unit || " is lighter than a gram"};
    ];
];

operator main{} [];
```
