# P0049: a transaction ended as SQL ends one

A transaction is a block, `transaction [ … ];`, which commits where it
ends, keeping what its statements did, and rolls back if one of them
fails, undoing them all. SQL ends a transaction with `COMMIT` or
`ROLLBACK`, which trendy has no statements for: a `commit;` is removed,
and a rollback is a failure, `fail e;`, with an error that says why,
which the transaction takes.

```trendy,error
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
};

operator main{} [
    transaction [
        update stock { sacks := sacks - 10 } where granary = "Accra";
        commit;
    ];
];
```

```trendy,error
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
};

operator main{} [
    transaction [
        update stock { sacks := sacks - 50 } where granary = "Accra";
        if count{r: stock where sacks < 0} > 0 then [
            rollback;
        ];
    ];
];
```

Written as trendy writes it, the transaction failing with an error of the
prelude's, `failure`, which it adds to `found`:

```trendy
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
};

operator main{} [
    var found: relation transaction_collection;
    transaction collecting found [
        update stock { sacks := sacks - 50 } where granary = "Accra";
        if count{r: stock where sacks < 0} > 0 then [
            fail failure{message: "Accra has too few sacks"};
        ];
    ];
    call debug_value{v: found};
];
```
