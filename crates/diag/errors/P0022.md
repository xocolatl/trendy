# P0022: operators that need parentheses

Precedence decides which of two operators written together applies first,
but trendy doesn't rank every pair. When a pair could reasonably be read
either way, neither reading is assumed, and parentheses must say which is
meant. The comparisons are one such case, since `a < b < c` doesn't chain
(P0015). There are three others.

**`!!` followed by an operator** that could apply either to the image or
to the relation it is of:

- a postfix operator: `.a`, a projection `{…}`, `remove`, `rename`,
  `extend`, `replace`, `group`, `ungroup`, `wrap` or `unwrap`;
- a join or a set operator: `join`, `times`, `compose`, `matching`,
  `union`, `intersect` or `minus`.

`!!` takes a single operand: a name, or an expression in parentheses.
After several operators, the image could be taken before any of them or
after all, so `!!r remove {a} times s` has three readings:
`(!!r) remove {a} times s`, `(!!(r remove {a})) times s` and
`!!(r remove {a} times s)`. The fix offers each.

```trendy,error
var births := relation { { name: "Ada", place: "London" } };
var cities := relation { { city: "London" } };
var natives := cities extend { natives := !!births rename {place as city} };

operator main{} [];
```

```trendy,error
var births := relation { { name: "Ada", place: "London" } };
var places := relation { { place: "London" } };
var names := places extend { names := !!births{name, place} };

operator main{} [];
```

**`union` followed by `minus`:** `r union s minus t` is
`r union (s minus t)` in the algebra, where `minus` is an AND and binds
like the joins, but `(r union s) minus t` in SQL, which reads set
operators from the left. The same holds of `d_union`, `xunion` and
`i_minus`. The
fix offers both.

```trendy,error
var born := relation { { name: "Ada" } };
var listed := relation { { name: "Wangari" } };
var gone := relation { { name: "Ada" } };
var current := born union listed minus gone;

operator main{} [];
```

**An `if` as an operand** of another operator: its `else` branch takes
all that follows, so in `1 + if c then 2 else 3 + 4` it could end at `3`
or at `4`. The fix parenthesizes the `if` where its `else` branch now
ends; move the `)` for the other reading. Where a whole value goes, as an
initial value, an argument or after `return`, an `if` needs none.

```trendy,error
operator total{n: integer, express: boolean}: integer [
    return n * 100 + if express then 500 else 0;
];

operator main{} [];
```

Parenthesize what each operator applies to:

```trendy
var births := relation { { name: "Ada", place: "London" } };
var cities := relation { { city: "London" } };
var natives := cities extend { natives := !!(births rename {place as city}) };
var places := relation { { place: "London" } };
var names := places extend { names := (!!births){name} };

var born := relation { { name: "Ada" } };
var listed := relation { { name: "Wangari" } };
var gone := relation { { name: "Ada" } };
var current := (born union listed) minus gone;

operator total{n: integer, express: boolean}: integer [
    return n * 100 + (if express then 500 else 0);
];

operator main{} [];
```
