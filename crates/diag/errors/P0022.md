# P0022: operators that need parentheses

Precedence decides which of two operators written together applies first,
but trendy doesn't rank every pair. When a pair could reasonably be read
either way, neither reading is assumed, and parentheses must say which is
meant. The comparisons are one such case, since `a < b < c` doesn't chain
(P0015). The other is `!!` followed by an operator that could apply
either to the image or to the relation it is of:

- a postfix operator: `.a`, a projection `{…}`, `remove`, `rename`,
  `extend`, `replace`, `group` or `ungroup`;
- a join: `join`, `times` or `compose`.

`!!` takes a single operand: a name, or an expression in
parentheses. After several operators, the image could be taken before any
of them or after all, so `!!r remove {a} times s` has three
readings: `(!!r) remove {a} times s`,
`(!!(r remove {a})) times s` and `!!(r remove {a} times s)`.
The fix offers each.

```trendy,error
var births := relation { { name: "Ada", place: "London" } };
var cities := relation { { city: "London" } };
var natives := cities extend { natives := !!births rename {place as city} };

operator main{} [];
```

```trendy,error
var births := relation { { name: "Ada", place: "London" } };
var places := relation { { place: "London" } };
var names := places extend { names := !!births{name, place} };

operator main{} [];
```

Parenthesize what the image is of, or the image itself:

```trendy
var births := relation { { name: "Ada", place: "London" } };
var cities := relation { { city: "London" } };
var natives := cities extend { natives := !!(births rename {place as city}) };
var places := relation { { place: "London" } };
var names := places extend { names := (!!births){name} };

operator main{} [];
```
