# A0059: a type's representations and their conversions

A type's values are stored as one of its possible representations, the
one without conversions. Each other converts to it with
`to { stored := … }`, computing the stored components from its own, and
from it with `from { own := … }`, computing its own from the stored
ones, so a value can be selected, and its components read, in any of
them (*The Third Manifesto*, RM Prescriptions 4 and 5). So a type has
exactly one representation without conversions, and each other has
both, the right way round:

```trendy,error
type temperature {
    { kelvin: approximate },
    { celsius: approximate },
};

operator main{} [];
```

```trendy,error
type temperature {
    { kelvin: approximate },
    { celsius: approximate } to { kelvin := celsius + 273.15e0 },
};

operator main{} [];
```

`to` that computes the representation's own components, and `from` the
stored ones, are swapped by the fix:

```trendy,error
type temperature {
    { kelvin: approximate },
    { celsius: approximate }
        to { celsius := kelvin - 273.15e0 }
        from { kelvin := celsius + 273.15e0 },
};

operator main{} [];
```

Store the values as one representation, and convert each other to it and
from it:

```trendy
type temperature {
    { kelvin: approximate },
    { celsius: approximate }
        to { kelvin := celsius + 273.15e0 }
        from { celsius := kelvin - 273.15e0 },
};

operator main{} [];
```
