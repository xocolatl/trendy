# R0023: a constraint broken

A constraint, `constraint name := condition;`, is a condition on a
unit's variables that holds whenever a statement ends, so no statement
can leave them in a state that breaks it (TTM RM Prescription 23). It
holds of the variables' initial values too, which are known when
compiling, so a constraint they break is reported then:

```trendy,error
var countries := relation { { country: "Kenya" } } key { country };
var official := relation {
    { language: "Swahili", country: "Kenya" },
    { language: "Quechua", country: "Peru" },
}
key { language, country };

constraint known_countries := official{country} <= countries;

operator main{} [];
```

The error says what breaks it where its form says which:

- `a <= b`: the tuples of `a` that aren't in `b`, and for `a >= b`, those
  of `b` that aren't in `a`. This is the shape of a foreign key: every
  country a language is official in is a country there is.
- `is_empty{r: e}`: the tuples of `e`.
- `c and d`: whichever of `c` and `d` is false, each with what breaks it.

Otherwise it says that the condition is false. Change the initial values,
or the constraint, so that it holds:

```trendy
var countries := relation { { country: "Kenya" }, { country: "Peru" } } key { country };
var official := relation {
    { language: "Swahili", country: "Kenya" },
    { language: "Quechua", country: "Peru" },
}
key { language, country };

constraint known_countries := official{country} <= countries;

operator main{} [];
```

A statement that assigns a variable a constraint mentions, an assignment,
an `assign` block, a call that passes it to a `var` or `out` parameter, or
a transaction that adds its errors to it, is checked as it ends, and one
that leaves the constraint false fails with R0023: a `constraint_violated
{ constraint, condition }`, the part of the condition that is false, or a
`constraint_violated_by { constraint, condition, tuples }`, with the
relation of the tuples that make it false where its form says which. A
transaction that collects its errors takes the failure, and gives the
variables back their values; otherwise the program stops. Here the
transaction refuses Esperanto, which is official nowhere, and keeps the
error:

```trendy
var languages := relation { { language: "Swahili" } } key { language };
var official := relation { { language: "Swahili", country: "Kenya" } } key { language, country };

constraint official_somewhere := languages <= official{language};

operator main{} [
    var refused: relation transaction_collection;
    transaction collecting refused [
        insert languages relation { { language: "Esperanto" } };
    ];
    call debug_value{v: count{r: languages}};
];
```

Changes that only hold together are made in one statement, an `assign`
block, which is checked once all its changes are made:

```trendy
var languages := relation { { language: "Swahili" } } key { language };
var official := relation { { language: "Swahili", country: "Kenya" } } key { language, country };

constraint official_somewhere := languages <= official{language};

operator main{} [
    assign {
        insert languages relation { { language: "Quechua" } };
        insert official relation { { language: "Quechua", country: "Peru" } };
    };
];
```
