# P0038: a mode written as another language writes one

A parameter is `const` unless it says otherwise: the operator only reads
its argument's value. A `var` parameter takes a variable instead, which
the operator can read and assign, and whose value when the operator ends
is the variable's (TTM, RM Prescription 3), and an `out` one takes a
variable whose value it never reads, as it assigns the parameter before
reading it. `var`, `const` or `out` is written before the parameter's
name, and a call marks its argument the same way, before the argument's
name:

```trendy
var cities := relation { tuple { name: "Lagos" } };

operator add_city{var r: relation { name: text }, name: text} [
    insert r relation { tuple { name: name } };
];

operator main{} [
    call add_city{var r: cities, name: "Osaka"};
];
```

Other languages' ways of writing a mode are fixed to trendy's: C#'s
`ref`, Swift's `inout` and Ada's `in out` are `var`, and Ada's `in` is
`const`.

```trendy,error
operator add_one{ref n: integer} [
    n := n + 1;
];

operator main{} [];
```

So is a mode written before the type, as Swift's `r: inout T` and Ada's
`N : out Integer`, or before the value in a call, as C#'s `f(ref x)` and
`f(out x)`, Swift's `f(&x)` and Rust's `f(&mut x)`, which goes before
the argument's name in trendy:

```trendy,error
var n := 1;

operator add_one{var n: integer} [
    n := n + 1;
];

operator main{} [
    call add_one{n: &n};
];
```

Tutorial D's `UPDATES { p }` clause, which lists the parameters an
operator updates, is fixed to `var` before each one's name:

```trendy,error
operator add_one{n: integer} updates {n} [
    n := n + 1;
];

operator main{} [];
```
