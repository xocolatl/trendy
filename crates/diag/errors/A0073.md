# A0073: a name more than one unit declares

A name a unit writes means one declaration it sees: one of its own, one
of the prelude's, or one of the interface of a unit its section uses. A
name more than one of those units declares means none of them, as nothing
settles which by order, so it is reported where it is written, with each
declaration. A unit that never writes the name compiles, so a unit that
gains a declaration breaks only the units that write its name. Operators
of one name whose parameters' names differ are overloads, and don't
clash. For the units `lakes/depths.trendy` and `seas/depths.trendy`:

```trendy,unit lakes.depths
interface

type metres { { m: integer } };
```

```trendy,unit seas.depths
interface

type metres { { m: integer } };
```

```trendy,error
uses { lakes.depths, seas.depths };

var depth := metres{m: 281};

operator main{} [];
```

A unit's own declaration clashes with a used unit's of its name too:

```trendy,error
uses { lakes.depths };

type metres { { m: integer } };
var depth := metres{m: 281};

operator main{} [];
```

Rename one of the declarations, or use only one of the units where the
name is written:

```trendy
uses { lakes.depths };

var depth := metres{m: 281};

operator main{} [];
```
