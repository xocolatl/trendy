# A0067: what a unit's interface can't declare

A unit's interface declares the types, headings and operators other
units see, each operator by its heading alone, and its implementation
gives each such operator's body, repeating its heading. The unit's
variables are its implementation's: other units reach them through its
update operators, so that what is true of them is the unit's to keep. So
are its versions of specifications, which dispatch finds whatever unit
calls them, so there is nothing about them to export. And what the
interface mentions, the types of its operators' parameters and results,
its headings' attributes, its types' components and supertypes, is in
the interface too, as other units see nothing else:

```trendy
interface

type metres { { m: integer } };

operator deepest{depths: relation { depth: metres }}: integer;

operator recorded{out count: integer};

implementation

var known := 0;

operator deepest{depths: relation { depth: metres }}: integer [
    max{r: depths, of: depth.m}
];

operator recorded{out count: integer} [
    count := known;
];

operator main{} [];
```

A variable in the interface moves to the implementation; an operator's
body there moves to its definition in the implementation, which repeats
its heading; and a type the interface mentions moves to the interface:

```trendy,error
interface

var known := 0;

operator deepest{depths: relation { depth: metres }}: integer [
    max{r: depths, of: depth.m}
];

implementation

type metres { { m: integer } };

operator main{} [];
```

A version in the interface moves to the implementation:

```trendy,error
interface

type too_deep is error { { m: integer } };

operator message{error: too_deep}: text [
    to_text{from: error.m} || " metres is too deep"
];

implementation

operator main{} [];
```
