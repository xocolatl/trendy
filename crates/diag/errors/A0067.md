# A0067: what a unit's interface can't declare, or must

A unit's interface declares the types, headings, operators and variables
other units see, each operator by its heading alone, and the constraints
on its variables, and its implementation gives each such operator's body,
repeating its heading. Other units read and assign the variables the
interface declares, so the constraints on those are the interface's too,
where every unit that assigns them sees them. The implementation keeps
its versions of specifications, which dispatch finds whatever unit calls
them, so there is nothing about them to export, and the variables only
its operators reach. And the interface sees only interfaces, while the
implementation sees both, so what the interface mentions anywhere, the
types of its operators' parameters and results, its headings' attributes,
its types' components, supertypes and constraints, its constants' values,
its variables' types and initial values and its constraints' conditions,
is in an interface too, as other units see nothing else:

```trendy
interface

type metres { { m: integer } };

operator deepest{depths: relation { depth: metres }}: integer;

var recorded := 0;

constraint counted := recorded >= 0;

implementation

operator deepest{depths: relation { depth: metres }}: integer [
    max{r: depths, of: depth.m}
];

operator main{} [];
```

A constraint in the implementation on a variable the interface declares
moves to the interface; an operator's body there moves to its definition
in the implementation, which repeats its heading; and a type the
interface mentions moves to the interface:

```trendy,error
interface

var recorded := 0;

operator deepest{depths: relation { depth: metres }}: integer [
    max{r: depths, of: depth.m}
];

implementation

type metres { { m: integer } };

constraint counted := recorded >= 0;

operator main{} [];
```

A variable only the implementation declares, which the interface
mentions, moves to the interface, so that other units read and assign it
too, unless what mentions it is a constraint on the implementation's
variables alone, which moves to the implementation instead, so that they
stay its own:

```trendy,error
interface

constraint counted := kept >= 0;

implementation

var kept := 0;

operator main{} [];
```

A version in the interface moves to the implementation:

```trendy,error
interface

type too_deep is error { { m: integer } };

operator message{error: too_deep}: text [
    to_text{from: error.m} || " metres is too deep"
];

implementation

operator main{} [];
```

A type's possible representations, its constraints and its order are in
the interface, as they say what its values are, but its
representations' conversions say how they are stored, which other units
don't see: with several representations, the implementation declares the
type again, repeating each one's components, with the conversions. So
conversions in the interface move to the implementation's declaration,
which the fix writes if it is missing, and a constraint or an order in
the implementation's declaration moves to the interface's:

```trendy,error
interface

type temperature {
    { kelvin: approximate },
    { celsius: approximate }
        to { kelvin := celsius + 273.15e0 }
        from { celsius := kelvin - 273.15e0 },
};

implementation

operator main{} [];
```

```trendy,error
interface

type temperature {
    { kelvin: approximate },
    { celsius: approximate },
};

implementation

type temperature {
    { kelvin: approximate },
    { celsius: approximate }
        to { kelvin := celsius + 273.15e0 }
        from { celsius := kelvin - 273.15e0 },
    constraint kelvin >= 0e0,
};

operator main{} [];
```

An operator a constraint in the interface calls is declared there by its heading,
which the fix writes, leaving its body in the implementation:

```trendy,error
interface

type percentage { { n: integer, constraint is_percentage{n} } };

implementation

operator is_percentage{n: integer}: boolean [
    n >= 0 and n <= 100
];

operator main{} [];
```

```trendy
interface

type percentage { { n: integer, constraint is_percentage{n} } };

operator is_percentage{n: integer}: boolean;

implementation

operator is_percentage{n: integer}: boolean [
    n >= 0 and n <= 100
];

operator main{} [];
```

The interface sees only its own `uses`, as each unit that uses this one
sees what the interface declares, so it must say where what it mentions
comes from; the implementation sees both sections' `uses`. A type or a
heading the interface mentions from a unit only the implementation uses
is fixed by using that unit in the interface instead. For the unit
`lakes/depths.trendy`:

```trendy,unit lakes.depths
interface

heading lake := { name: text, depth: integer };
```

```trendy,error
interface

operator count_of{lakes: relation lake}: integer;

implementation

uses { lakes.depths };

operator count_of{lakes: relation lake}: integer [ count{r: lakes} ];

operator main{} [];
```
