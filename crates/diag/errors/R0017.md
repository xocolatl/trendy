# R0017: a value that breaks its type's constraint

A type's constraints say which values it has: each is a condition on the
components, and a value of the type is one whose components satisfy them
all (*The Third Manifesto*, RM Prescription 23). Every value of the type
is selected from its components, by its selector, `replace` or `update`,
or from a file's fields by `load_csv`, so it is there that a constraint
is checked: selecting a value from
components that break one fails, and no variable ever holds a value
outside its type.

When the components are known while compiling, a constraint they break
is reported there:

```trendy,error
type percentage {
    { value: integer },
    constraint value >= 0 and value <= 100,
};

var discount := percentage{value: 120};

operator main{} [];
```

```trendy,error
type position {
    { latitude: approximate, longitude: approximate },
    constraint latitude >= -90e0 and latitude <= 90e0,
};

var north := position{latitude: 89e0, longitude: 0e0} replace { latitude := latitude + 2e0 };

operator main{} [];
```

When they are known only when the program runs, the program stops
instead, writing the value and the constraint to stderr, as in
`error[R0017]: percentage{value: 120} isn't a value of percentage: it
breaks the constraint value >= 0 and value <= 100`, and exiting with
status 1. A value `load_csv` reads from a file is checked as it is
read, and the error names the line of the record, and the attribute,
too.

Select only values whose components satisfy the constraints, checking
them first where the components come from outside the program:

```trendy
type percentage {
    { value: integer },
    constraint value >= 0 and value <= 100,
};

var discount := percentage{value: 20};

operator main{} [];
```
