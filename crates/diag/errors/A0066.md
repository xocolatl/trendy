# A0066: input or output in a transaction

A transaction's statements read no input and write no output, at any
depth of the calls they make. A transaction is all done or none of it
is: if a statement in it fails, it undoes them all, and a database can
run one again that conflicts with another. Nothing undoes a read or a
write, so a file read in a transaction would be read again, and what
was written would stay written. `debug_value` and `debug_table` write
for the programmer, so they are exempt.

```trendy,error
heading post := { slug: text, title: text };

var posts: relation post := relation {};

operator import{path: text} [
    var rows: array tuple post;
    call load_csv{path: path, header: true, columns: tuple { slug: 1, title: 2 }, out rows: rows};
    var read: relation post;
    load read from rows;
    insert posts read;
];

operator main{} [
    var found: relation { error: error };
    transaction collecting found [
        call import{path: "posts.csv"};
    ];
];
```

Read the file before the transaction, and give what it read to the
statements in it, which only change variables:

```trendy
heading post := { slug: text, title: text };

var posts: relation post := relation {};

operator import{rows: array tuple post} [
    var read: relation post;
    load read from rows;
    insert posts read;
];

operator main{} [
    var rows: array tuple post;
    call load_csv{path: "posts.csv", header: true, columns: tuple { slug: 1, title: 2 }, out rows: rows};
    var found: relation { error: error };
    transaction collecting found [
        call import{rows: rows};
    ];
];
```

To write what a transaction decides, keep it in a variable the
transaction assigns, which its rollback undoes with the rest, and write
it after the transaction.
