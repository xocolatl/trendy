# A0072: units that use each other

No unit uses itself, through any path: a unit's interface is known before
each unit that uses it is checked, so the units are checked in an order
where each comes after those it uses. This is the catalog's constraint
`acyclic`, that `uses{unit, used} tclose where unit = used` is empty. A
cycle of `uses` is reported at the first unit's, with each other unit's
on the way round. For the units `lakes/depths.trendy` and
`lakes/names.trendy`, which use each other:

```trendy,unit lakes.depths
uses { lakes.names };
```

```trendy,unit lakes.names
uses { lakes.depths };
```

```trendy,error
uses { lakes.depths };

operator main{} [];
```

What the units need of each other goes in a unit of its own, which each
uses, or in the one of them the other uses:

```trendy,unit lakes.names
interface

heading name := { name: text, native: text };
```

```trendy,unit lakes.depths
uses { lakes.names };
```

```trendy
uses { lakes.depths };

operator main{} [];
```

A unit that uses itself has nothing to gain by it, so the fix removes its
own name from its `uses`.
