# A0031: operands of different headings

`union`, `d_union`, `xunion`, `intersect`, `minus` and `i_minus` combine
the tuples of relations, so the relations must have the same attributes,
each of one type in both. A tuple of one with an attribute the other
lacks couldn't be a tuple of the result.

```trendy,error
var people := relation { { name: "Ada", city: "London" } };
var more := relation { { name: "Wangari", town: "Nyeri" } };
var everyone := people union more;

operator main{} [];
```

When each operand has one attribute the other lacks, of the same type,
it is likely one attribute named two ways, and the fix renames it.
Otherwise, project or extend an operand to the other's heading:

```trendy
var people := relation { { name: "Ada", city: "London" } };
var more := relation { { name: "Wangari", town: "Nyeri" } };
var everyone := people union more rename {town as city};
var names := people{name} union more{name};

operator main{} [];
```

Of types in one hierarchy (*Type Inheritance and Relational Theory*, IM
Prescription 13), a union's attribute is of the most specific type both
operands' are, so they must have one. An intersection's and a
difference's tuples are compared, so each attribute's types must be one
a subtype of the other, as for `=`: a union type's subtypes are disjoint,
so `ellipses minus polygons` would be `ellipses` whatever their values.

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

var ellipses := relation { { name: "pond", figure: ellipse{a: 3e0, b: 2e0} } };
var polygons := relation { { name: "plot", figure: polygon{corners: 4} } };
var others := ellipses minus polygons;

operator main{} [];
```
