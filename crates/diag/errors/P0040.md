# P0040: a type's constraint written as in SQL

A type's constraints, each `constraint` and a condition on its
components, go in its braces with its possible representation: they say
which values the type has (*The Third Manifesto*, RM Prescription 23).
SQL writes a domain's condition, and a table's, after `CHECK`, which the
fix writes `constraint`.

```trendy,error
type percentage {
    { value: integer },
    check value >= 0 and value <= 100,
};

operator main{} [];
```

Write `constraint`:

```trendy
type percentage {
    { value: integer },
    constraint value >= 0 and value <= 100,
};

operator main{} [];
```
