# A0044: `per` argument the same for every tuple

A `per r` argument is computed for each tuple of `r`, with the tuple's
attributes in scope by name, as in `where`. One that uses none of them is
the same for every tuple, so the operator's result would depend only on
how many tuples there are: the max of a value for each tuple is that
value, and its sum that many times it. That is never what an aggregate is
for, so it is an error. Tutorial D's aggregates take an attribute of the
relation; a `per` argument can compute from several, but must use one.

Naming an attribute in double quotes, as SQL names a column, makes a text,
which the fix makes the attribute:

```trendy,error
var readings := relation {
    { station: "Nairobi", celsius: 14 },
    { station: "Ulaanbaatar", celsius: -21 },
};
var high := max{r: readings, of: "celsius"};

operator main{} [];
```

A name that isn't an attribute of `r`'s tuples is found outside them: in
an image relation, `!!r`, the attributes it shares with the tuple at hand
aren't its own, so `station` here is the tuple's of `stations`, the same
for each reading:

```trendy,error
var stations := relation { { station: "Nairobi" }, { station: "Ulaanbaatar" } };
var readings := relation {
    { station: "Nairobi", hour: 6, celsius: 14 },
    { station: "Ulaanbaatar", hour: 6, celsius: -21 },
};
var last := stations extend { name := max{r: !!readings, of: station} };

operator main{} [];
```

Compute the argument from the attributes of `r`'s tuples. For a value the
same for every tuple, use it outside the aggregate: the number of tuples
is `count{r: r}`, and whether there is one `r <> relation {}`.

```trendy
var stations := relation { { station: "Nairobi" }, { station: "Ulaanbaatar" } };
var readings := relation {
    { station: "Nairobi", hour: 6, celsius: 14 },
    { station: "Ulaanbaatar", hour: 6, celsius: -21 },
};
var high := max{r: readings, of: celsius};
var latest := stations extend { hour := max{r: !!readings, of: hour} };

operator main{} [];
```
