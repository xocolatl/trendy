# A0051: a mode where a parameter can't have one

A parameter is `const` unless it is written `var` or `out`: the
operator only reads its argument's value. A `var` parameter takes a
variable instead, which the operator can read and assign, and whose
value is the parameter's when the operator ends (TTM, RM Prescription
3), and an `out` one a variable it assigns before reading it.

Only an update operator's parameters can be `var` or `out`. A read-only
operator computes a value and changes nothing but its own local
variables:

```trendy,error
operator doubled{var n: integer}: integer [
    n * 2
];

operator main{} [];
```

Nor can a `per` parameter, whose argument is a value for each tuple of
its relation, or that relation, whose tuples carry those values:

```trendy,error
operator total{var r: any relation, of: integer per r} [];

operator main{} [];
```

And only an operator's parameters have a mode at all, not the attributes
of a tuple or relation type:

```trendy,error
var t: tuple { var a: integer } := tuple { a: 1 };

operator main{} [];
```

Remove the mode, or make the operator an update operator, which `call`
invokes, to change a variable it is passed:

```trendy
operator double{var n: integer} [
    n := n * 2;
];

var count := 21;

operator main{} [
    call double{var n: count};
];
```
