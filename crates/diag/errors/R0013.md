# R0013: a file, or standard input, isn't UTF-8 text

A `text` value is Unicode, encoded as UTF-8, so `load_text_file` and
`load_csv` read only a file that is UTF-8 text, and `read`, of
`trendy.streams`, only standard input that is, as lines. When the program
runs, it stops at the first line that isn't, writing the line's number and
the path to stderr, as in `error[R0013]: line 3 of "rivers.txt" isn't UTF-8
text`, or `line 3 of standard input isn't UTF-8 text`, a `not_utf8_input`,
and exits with status 1. Bytes that aren't text are read as bytes, with
`load_binary_file` or `read{out bytes}`. A file in another encoding, such
as Latin-1 or UTF-16, has to be converted first, with a tool such as
`iconv`, as in `iconv -f LATIN1 -t UTF-8 rivers.txt > rivers-utf8.txt`.

The compiler never opens the file, so this is reported only when the
program runs:

```trendy
uses { trendy.files };

operator main{} [
    var lines: array text;
    call load_text_file{path: file_path{text: "rivers-utf8.txt"}, out lines: lines};
    call debug_value{v: lines};
];
```
