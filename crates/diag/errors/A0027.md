# A0027: common attribute of different types

`join` and `compose` match the tuples of their operands on the attributes
they have in common, by name, and so do `matching` and `not matching`. A
value matches only an equal value, which is of its type, since values
never convert to another type implicitly, so an attribute the operands
share must be of one type in both, or of types one of which is a subtype
of the other, which the result's is (*Type Inheritance and Relational
Theory*, IM Prescription 13).

```trendy,error
var cities := relation { { city: "Kumasi", country: "GH" } };
var countries := relation { { country: 288, name: "Ghana" } };
var placed := cities join countries;

operator main{} [];
```

`!!r` matches `r` with the tuple at hand the same way:

```trendy,error
var countries := relation { { country: 288, name: "Ghana" } };
var cities := relation { { city: "Kumasi", country: "GH" } };
var by_country := countries extend { cities := !!cities };

operator main{} [];
```

A union type's subtypes are disjoint, so attributes of two of them never
match, and the join would have no tuples whatever its operands' values:

```trendy,error
type plane_figure union;
type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

var ellipses := relation { { name: "pond", figure: ellipse{a: 3e0, b: 2e0} } };
var polygons := relation { { name: "plot", figure: polygon{corners: 4} } };
var both := ellipses join polygons;

operator main{} [];
```

If the two attributes mean different things, rename one, so that they
aren't matched; if they mean the same thing, write it the same way in both:

```trendy
var cities := relation { { city: "Kumasi", country: "GH" } };
var countries := relation { { country: 288, name: "Ghana" } };
var both := cities times countries rename {country as country_number};

operator main{} [];
```
