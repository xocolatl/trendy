# P0019: key written as in SQL

A relation variable's keys are each written `key { … }`, after its value.
SQL's `PRIMARY KEY` and `UNIQUE` both mean a key in trendy, so the fix
writes `key`.

trendy has no primary key. Every key is a candidate key, and when a variable
has several, none of them is more important than the others. *The Third
Manifesto* doesn't require one key to be singled out as primary, and Date
calls the practice "a psychological issue merely".

```trendy,error
var cities := relation {
    { name: "Lagos", country: "Nigeria" },
    { name: "Osaka", country: "Japan" },
}
    primary key { name };

operator main{} [];
```

```trendy,error
var codes := relation { { code: "KE", country: "Kenya" } }
    unique { code }
    unique { country };

operator main{} [];
```

Write `key`, once for each key:

```trendy
var cities := relation {
    { name: "Lagos", country: "Nigeria" },
    { name: "Osaka", country: "Japan" },
}
key { name };

var codes := relation { { code: "KE", country: "Kenya" } } key { code } key { country };

operator main{} [];
```
