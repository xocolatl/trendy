# A0003: unknown type

A type's name, or a heading's, is not one. The built-in types are
`boolean`, `true` or `false`; `integer`, a 64-bit signed integer;
`approximate`, a 64-bit floating-point number; and `text`, a UTF-8
string. Inside an operator, its type parameters are types too. Names are
case-sensitive, and the type names of other languages, such as `bool`,
`int`, `double` or `string`, are not used.

```trendy,error
var i: int := 0;

operator main{} [];
```

```trendy,error
var t: String := "hello";

operator main{} [];
```

Use a built-in type:

```trendy
var i: integer := 0;
var t: text := "hello";

operator main{} [];
```

After `any`, the name is a kind: one of the prelude's, such as `ordered`.

```trendy,error
operator before{a: T, b: T}: boolean types { T: any ordred } [
    a < b
];

operator main{} [];
```

```trendy
operator before{a: T, b: T}: boolean types { T: any ordered } [
    a < b
];

operator main{} [];
```

A parameter that takes a value of any type is `any type`, not `any`, as
TypeScript and Go write it, or PostgreSQL's `anyelement`:

```trendy,error
operator show{v: any} [
    call debug_value{v: v};
];

operator main{} [];
```

```trendy
operator show{v: any type} [
    call debug_value{v: v};
];

operator main{} [];
```

After `relation` or `tuple` comes a heading: its attributes in braces, or
the name of one declared with `heading`. A heading's name alone is not a
type, as a type of records' is in other languages: a heading is the
attributes of tuples and relations alike, so its types are
`relation home` and `tuple home`, and the fix writes either.

```trendy,error
heading home := { city: text, rooms: integer };

operator describe{h: home} [];

operator main{} [];
```

```trendy,error
heading home := { city: text, rooms: integer };

var homes: relation hom;

operator main{} [];
```

```trendy
heading home := { city: text, rooms: integer };

var homes: relation home;

operator describe{h: tuple home} [];

operator main{} [];
```
