# P0041: a constraint or an order inside the components' braces

A type's constraints, each `constraint` and a condition on its
components, go in the type's braces, with its possible representation,
not in the representation's own: they are the type's, and say which
values it has (*The Third Manifesto*, RM Prescription 23). So does its
order, `order [asc …]`. Tutorial D writes a possible representation's
`CONSTRAINT` inside its braces, after its components, and a type has one
constraint whatever the representation it is written in. The fix moves
the constraint, or the order, after the components' braces:

```trendy,error
type angle { { radians: approximate, constraint radians >= 0e0 } };

operator main{} [];
```

```trendy,error
type angle { { radians: approximate constraint radians >= 0e0 } };

operator main{} [];
```

Put the constraint in the type's braces:

```trendy
type angle {
    { radians: approximate },
    constraint radians >= 0e0,
};

operator main{} [];
```
