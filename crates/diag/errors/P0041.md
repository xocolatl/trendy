# P0041: a type's constraint or order inside the components' braces

A type's constraints, each `constraint` and a condition on its
components, go in the type's braces, with its possible representation,
not in the representation's own: they are the type's, and say which
values it has (*The Third Manifesto*, RM Prescription 23). So does its
order, `order [asc …]`. Tutorial D writes a possible representation's
`CONSTRAINT` inside its braces, after its components. In trendy, a
representation that converts to the stored one can have constraints of
its own there, which say which of its components represent a value, but
the stored representation's components are a value's, so a constraint in
its braces is the type's, and an order is a type's in any
representation's. The fix moves the constraint, or the order, after the
components' braces:

```trendy,error
type angle { { radians: approximate, constraint radians >= 0e0 } };

operator main{} [];
```

```trendy,error
type angle { { radians: approximate constraint radians >= 0e0 } };

operator main{} [];
```

Put the constraint in the type's braces:

```trendy
type angle {
    { radians: approximate },
    constraint radians >= 0e0,
};

operator main{} [];
```
