# A0064: a type's key among what it says of itself

A type's key is a rule of one of its relation-valued components: no two
tuples of the component's relation have the same values for the key's
attributes, in any value of the type. So it is written after that
component's type, as a relation variable's key is after its own, and not
among the type's constraints and order, where it couldn't say which
component it keys:

```trendy,error
type outline {
    { vertices: relation { v_no: integer, x: approximate, y: approximate } },
    key { v_no },
};

operator main{} [];
```

When one relation-valued component has the key's attributes, the fix
moves the key after its type:

```trendy
type outline {
    { vertices: relation { v_no: integer, x: approximate, y: approximate } key { v_no } },
};

operator main{} [];
```

When several have them, the error lists them, and the key goes after the
type of the one it is a rule of.
