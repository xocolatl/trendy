# A0074: a representation's constraint names another's component

A possible representation can have constraints of its own, in its
braces after its components, which say which of them represent a value:
`tens{big: 15}` is no value of `tens` below, though `big div 10` would
make one. Selecting a value in that representation, by its selector,
`replace`, `update` or `load_csv`, checks them of the components as
given, before its `to` converts them, so they can name its own
components alone, not another representation's. The stored
representation's own hold of every value, as its components are every
value's, but they name its own components alone too, so that nothing in
them tells the type's users which representation the values are stored
as:

```trendy,error
type tens {
    { n: integer },
    { big: integer, constraint big mod 10 = 0 and n > 0 }
        to { n := big div 10 }
        from { big := n * 10 },
};

operator main{} [];
```

The type's constraints, in the type's braces, are checked of every value,
in any representation, so they can name any representation's
components. The fix moves the constraint there; or split it, keeping
what is about the representation's own components in its braces:

```trendy
type tens {
    { n: integer },
    { big: integer, constraint big mod 10 = 0 }
        to { n := big div 10 }
        from { big := n * 10 },
    constraint n > 0,
};

operator main{} [];
```
