# A0076: a bit operator grouped with a comparison

`not`, `and`, `or` and `xor` are the operators of booleans, and of
integers, bit by bit, with the same precedence either way. `not` binds
tightest, as every prefix operator does, and `and`, `or` and `xor`
looser than a comparison, which leaves two writings that other languages
read otherwise, or that make no sense as written.

A comparison takes the operand next to it, so `flags and 4 = 4` is
`flags and (4 = 4)`, `and` of an integer and a boolean, as `flags & 4 ==
4` is in C. Where the comparison's operand next to the integer is an
integer too, the comparison of bits was meant, and the fix
parenthesizes it, `(flags and 4) = 4`:

```trendy,error
operator readable{mode: integer}: boolean [ mode and 0o444 <> 0 ];

operator main{} [];
```

`not n = 0` is `(not n) = 0`, the complement of `n` compared, which SQL
and Python read as `not (n = 0)`, the comparison negated. A `not` of an
integer that begins a comparison is written in parentheses, whichever is
meant, so that neither is assumed; the help shows both:

```trendy,error
operator full{mask: integer}: boolean [ not mask = 0 ];

operator main{} [];
```

Parenthesize what is meant:

```trendy
operator readable{mode: integer}: boolean [ (mode and 0o444) <> 0 ];
operator full{mask: integer}: boolean [ (not mask) = 0 ];
operator nonzero{mask: integer}: boolean [ not (mask = 0) ];

operator main{} [];
```
