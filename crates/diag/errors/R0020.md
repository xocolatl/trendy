# R0020: a value of two subtypes defined by constraints

A subtype of a type with possible representations is defined by its
constraints: a value of the type is one of the subtype exactly when they
are true of it (*Type Inheritance and Relational Theory*, IM Prescription
10). A value has one most specific type, so two subtypes of one type,
neither a subtype of the other, can't both have it: their constraints
must never both be true. A value selected of the type that is of both is
an error, when compiling if its components are known then:

```trendy,error
type ellipse { { a: approximate, b: approximate }, constraint a >= b };
type circle is ellipse { constraint a = b };
type small is ellipse { constraint a < 1e0 };

var dot := ellipse{a: 5e-1, b: 5e-1};

operator main{} [];
```

and otherwise when the program runs, which stops, writing the value and
the two types, as in ``error[R0020]: ellipse{a: 5e-1, b: 5e-1} is of
both `circle` and `small`, but a value has one most specific type``,
unless a transaction takes its error, an `overlapping_subtypes { value,
first, second }`.

Change a constraint so that no value is of both, or make one a subtype of
the other, whose values are then among its own:

```trendy
type ellipse { { a: approximate, b: approximate }, constraint a >= b };
type circle is ellipse { constraint a = b };
type small is ellipse { constraint a < 1e0 and a > b };

var dot := ellipse{a: 5e-1, b: 5e-1};

operator main{} [];
```
