# A0082: a transaction's start read outside any transaction

`transaction_start` gives the instant the outermost transaction running
began, which only exists while one runs. So every call that reads it has to
run in a transaction, at some depth of the calls that lead to it. A call in
`main` that isn't in a transaction, and that leads to it through calls that
aren't in one either, can't have one running.

```trendy,error
uses { trendy.time };

operator stamp{out at: timestamp} [
    call transaction_start{out at};
];

operator main{} [
    var at: timestamp;
    call stamp{out at};
    call debug_value{v: at.date.year};
];
```

Call it in a transaction, or read the clock with `now`, which is the instant it
is, and which a transaction's statements can't call (A0066). An operator that
reads a transaction's start can be called from any transaction, and code can
begin one without knowing if it is nested in another: each gets the outermost's.

```trendy
uses { trendy.time };

operator stamp{out at: timestamp} [
    call transaction_start{out at};
];

operator main{} [
    var at: timestamp;
    transaction [
        call stamp{out at};
    ];
    call debug_value{v: at.date.year >= 2024};

    var checked: timestamp;
    call now{out at: checked};
    call debug_value{v: checked.date.year >= 2024};
];
```
