# A0078: a constraint in an operator's braces that can't be one

A constraint in an operator's braces says which arguments a call of it can
have: a condition on its parameters, which each call checks first, and which
fails where the call is when it is false (R0024). So it reads at least one of
them, as a condition that reads none says nothing of a call:

```trendy,error
operator half{n: integer, constraint 1 > 0}: integer [
    n div 2
];

operator main{} [];
```

It reads only what has a value when the call is made, so neither an `out`
parameter, which the operator hasn't assigned yet, nor a `per` parameter,
which has a value for each tuple. A `var` parameter's value is its variable's
as the call starts:

```trendy,error
operator count_down{n: integer, out left: integer, constraint left > n} [
    left := n;
];

operator main{} [];
```

Other units see only a unit's interface, and what a call can be given is for
its callers to see, so an operator its interface declares has its constraints
there. The fix moves one written in the definition:

```trendy,error
interface

operator half{n: integer}: integer;

implementation

operator half{n: integer, constraint n >= 0}: integer [
    n div 2
];

operator main{} [];
```

A version of a specification has none of its own, as a call of the
specification can't say which version it will compute:

```trendy,error
type figure union;
type round is figure { { r: integer } };
type square is figure { { s: integer } };

operator area{f: figure}: integer;

operator area{f: round, constraint f.r > 0}: integer [
    3 * f.r * f.r
];

operator area{f: square}: integer [
    f.s * f.s
];

operator main{} [];
```

Write it in the braces of the operator its callers see, with the parameters
it is about:

```trendy
operator half{n: integer, constraint n >= 0}: integer [
    n div 2
];

operator main{} [
    call debug_value{v: half{n: 7}};
];
```
