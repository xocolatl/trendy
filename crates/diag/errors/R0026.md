# R0026: a file that can't be written

`save_text_file` writes the file at its `path` when the program runs, as
`write`, of `trendy.streams`, writes at the end of one, `to: file{path}`, and
the program stops if it can't: if the directory it is in doesn't exist, if
the program isn't allowed to write there, if `path` is a directory, or if the
disk fills up. It writes the path and the system's reason to stderr, as in
`error[R0026]: can't write "rivers/list.txt": No such file or directory`, and
exits with status 1. A failure partway, as on a full disk, can leave part of
the lines in the file, and what it held before is gone.

The compiler never opens the file, so this is reported only when the program
runs. A relative path is relative to the directory the program runs in, not
the one its source is in:

```trendy
uses { trendy.files };

operator main{} [
    call save_text_file{path: file_path{text: "rivers.txt"}, lines: array ["Nile", "Paraná"]};
];
```

A missing directory isn't made: make it first. To carry on rather than stop,
name `out errors`, which is empty when the file is written, and which
otherwise holds an `unwritable_file { path, reason }`:

```trendy
uses { trendy.files };

operator main{} [
    var errors: relation { error: error };
    call save_text_file{path: file_path{text: "rivers.txt"}, lines: array ["Nile"], out errors: errors};
    call debug_value{v: errors};
];
```
