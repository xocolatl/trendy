# A0050: a read-only operator reads a variable of the program's

A read-only operator is a function of its arguments: its calls with the
same arguments have the same value, whenever they are made (TTM, RM
Prescription 3). A type's constraint, a condition on its components, is
one too, since it says which values the type has: one that read a
variable would make a value of the type one at one time and not at
another. So it reads only its parameters and its own local
variables, not the program's variables, whose values change when the
program runs. A variable it needs is passed to it, as a `const`
parameter, as the fix does, giving it the variable in each call:

```trendy,error
var vat := 16;

operator taxed{price: integer}: integer [
    price + price * vat div 100
];

operator main{} [
    call debug_value{v: taxed{price: 100}};
];
```

Pass the variable as an argument:

```trendy
var vat := 16;

operator taxed{price: integer, vat: integer}: integer [
    price + price * vat div 100
];

operator main{} [
    call debug_value{v: taxed{price: 100, vat: vat}};
];
```

An update operator, which a `call` invokes, can read the program's
variables, and assign them.

A type's constraint has no parameters to pass a variable as, and no fix:
it is written with the components and constants alone.

```trendy,error
var limit := 100;

type percentage {
    { value: integer },
    constraint value >= 0 and value <= limit,
};

operator main{} [];
```

```trendy
type percentage {
    { value: integer },
    constraint value >= 0 and value <= 100,
};

operator main{} [];
```
