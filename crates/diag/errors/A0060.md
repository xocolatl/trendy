# A0060: a union type and its subtypes

A union type has no values of its own: each of its values is a value of
one of its subtypes, each a type declared `is` it (*Type Inheritance and
Relational Theory*, chapter 12, IM Prescription 20). A union type without
a possible representation is a dummy type, and so it has no selector, no
components, and no braces; its subtypes have possible representations of
their own:

```trendy
type plane_figure union;

type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator main{} [];
```

So a union type with braces is an error. A union type with a possible
representation of its own, whose subtypes are specialized by constraints,
as Date's circles are ellipses whose semiaxes are equal, isn't in trendy
yet:

```trendy,error
type ellipse union { { a: approximate, b: approximate } };

type circle is ellipse { { r: approximate } };
type oval is ellipse { { a: approximate, b: approximate } };

operator main{} [];
```

Only a union type has subtypes, so a type declared `is` a type with a
possible representation, or a built-in type, is an error:

```trendy,error
type ellipse { { a: approximate, b: approximate } };

type circle is ellipse { { r: approximate } };

operator main{} [];
```

A union type with one subtype would have the same values as it, and with
none it would have no values, so a union type has two subtypes at least
(exercise 12.4):

```trendy,error
type plane_figure union;

type ellipse is plane_figure { { a: approximate, b: approximate } };

operator main{} [];
```
