# A0081: an attribute compared with itself

In a `where`, an `extend` and the like, a tuple's attributes are in scope by name, and
they hide any other name they share, so a name there means the attribute, on both sides
of a comparison. `n = n` is then true of every tuple, and `n <> n` of none, which is
never what was meant. It is usually a comparison with a parameter or a variable of the
same name, which the attribute hides:

```trendy,error
operator named{cities: relation { n: text, people: integer }, n: text}: relation { n: text, people: integer } [
    cities where n = n
];

operator main{} [];
```

The attribute hides it only in the `where`, so read it into a constant before that, and
compare the attribute with the constant. The fix does this for `=` and `<>`, which read
the same either way round, with a name nothing there has. For `<` and the like, say which
side it is. A parameter keeps its name this way, which its callers write in their
arguments, and they stay as they are:

```trendy
operator named{cities: relation { n: text, people: integer }, n: text}: relation { n: text, people: integer } [
    const wanted := n;
    cities where n = wanted
];

operator main{} [];
```

A constant can't always read it: not an attribute of a tuple further out, nor a program's
variable outside an update operator, nor anything in a `while`'s condition, which is
computed again after what the loop changes. Rename that instead.

With nothing hidden, the comparison was meant of something else, or says nothing:

```trendy,error
var cities := relation { { n: "Lagos", people: 15 } };
var all := cities where n = n;

operator main{} [];
```

```trendy
var cities := relation { { n: "Lagos", people: 15 } };
var lagos := cities where n = "Lagos";

operator main{} [];
```
