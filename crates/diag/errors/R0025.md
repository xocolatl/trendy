# R0025: calls that went too deep

Each call was left waiting for the one it made, as it had work to do once that
one returned, until together they used up the stack. Which call fails depends
on how deep they went, so the program stops there, writing the error and the
innermost and outermost of the calls, unless a transaction takes the error, a
`too_deep { bytes }`, whose `bytes` is the stack's size. This one fails, as each
`sum_to` has `n +` left to do:

```trendy
operator sum_to{n: integer}: integer [
    if n = 0 then 0 else n + sum_to{n: n - 1}
];

operator main{} [
    var n := 100_000_000;
    call debug_value{v: sum_to{n: n}};
];
```

Have the call take what it needs to finish, so that nothing is left to do after
it. A tail call needs no stack, however many follow (see
[Recursion](#recursion) in the language reference):

```trendy
operator sum_to{n: integer, so_far: integer}: integer [
    if n = 0 then so_far else sum_to{n: n - 1, so_far: so_far + n}
];

operator main{} [
    var n := 100_000_000;
    call debug_value{v: sum_to{n: n, so_far: 0}};
];
```

A call for each tuple of an `extend` or a `where` always has work left, and
those that go too deep usually never would have ended, on a cycle in the data
they walk. Then the fix is in the data, or in what the calls pass along: the
values visited so far, which they leave out.
