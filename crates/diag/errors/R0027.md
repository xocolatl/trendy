# R0027: a line to write that wouldn't read back as one line

`save_text_file` writes each element of `lines` with a line feed after it, so
that `load_text_file` reads the same lines back. An element with a line feed in
it would read back as two lines, and one that ends in a carriage return would
lose it, as a carriage return and a line feed are one line end. So the program
stops before anything is written, which leaves a file already there as it was,
writing the element's position, counting from 1, to stderr, as in
`error[R0027]: line 2 to write to "rivers.txt" wouldn't read back as one line:
it has a line feed in it, or ends in a carriage return`, and exits with status
1.

Lines usually come from elsewhere, so this is reported only when the program
runs. `out errors` doesn't take it, as it is a mistake in the call and not the
file's. Split a text that has several lines into its lines first:

```trendy
uses { trendy.files };

operator main{} [
    call save_text_file{path: "rivers.txt", lines: array ["Nile", "Paraná"]};
];
```
