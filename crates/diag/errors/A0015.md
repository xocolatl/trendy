# A0015: unknown name

A name refers to no parameter, variable or operator in scope. Inside an
operator, a name is looked up first among the operator's parameters, then
among the program's variables; a call's operator is looked up among the
operators, including the built-ins. When a defined name is close, the fix
replaces it: one at most two edits away, of which a letter stays as it is,
so `a` is another name than `n`, not a misspelling of it.

```trendy,error
var count := 1;

operator main{} [
    call debug_value{v: cout};
];
```

```trendy,error
operator main{} [
    call debug_valu{v: 1};
];
```

Other languages' names for the operators that come with the compiler,
such as Python's `prod` and `len`, aren't close in spelling to trendy's,
or are closer to another, as `len` is to `min`, so the fix names
trendy's, `product`, and `count` of a relation or `length` of an array,
as it does for SQL's `CARDINALITY` and Java's `size`. Its argument is
named as the operator's parameter, too, written in Python's way,
`len(rainfall)`, once its parentheses are braces:

```trendy,error
var harvests := relation { { crop: "wheat", tonnes: 950 }, { crop: "tea", tonnes: 120 } };
var crops := len{r: harvests};

operator main{} [];
```

```trendy,error
var rainfall := array [1200, 950, 220];
var months := len{rainfall};

operator main{} [];
```

R's and Kotlin's `readLines`, Python's and Ruby's `readlines`, and
.NET's `ReadAllLines` read a file's lines, as `load_text_file` does, which
`trendy.files` declares, so the fix uses it too, unless the unit does:

```trendy,error
operator main{} [
    var lines := readLines{"rivers.txt"};
    call debug_value{v: lines};
];
```

Rust's `chars` and Java's `codePoints` give a text's code points, as
`to_code_points` does, and JavaScript's `String.fromCodePoint` the text
of some, as `from_code_points` does. Python's `ord` and `chr`, and
JavaScript's `String.fromCharCode` of one number, are a code point's
number and its text, which `code_point` gives, so the fix writes them
with it: `code_point{character: c}.value` and `code_point{value:
n}.character`. JavaScript's `charCodeAt`, of a position, gets help:

```trendy,error
var word := "Zürich";
var points := chars{word};
var letter := "ü";
var number := ord{letter};
var accent := chr{769};

operator main{} [];
```

The sine and cosine called `sine` and `cosine`, and NumPy's `arctan2`,
are fixed to `sin`, `cos` and `atan2`. A mathematical function the
prelude hasn't yet, such as `tan`, `log` or `abs`, is no misspelling of
one it has, though `log` is close to `cos` and `atan` to `atan2`, so it
has no fix: the error says how to write its value with the prelude's
operators, where they can:

```trendy,error
var slope := tan{of: 5e-1};

operator main{} [];
```

A constant, as other languages write one, such as `PI`, C's `M_PI`,
Python's `math.pi` or JavaScript's `Math.PI`, is fixed to the call of
the read-only operator without parameters that gives its value, as
`pi{}` does:

```trendy,error
var circumference := 2e0 * Math.PI * 1.5e0;

operator main{} [];
```

A value named `ARRAY`, `Array` or another spelling of the keyword
`array`, indexed, as SQL writes an array of one element, `ARRAY[1]`, is
fixed to an array selector:

```trendy,error
var one := ARRAY[1];

operator main{} [];
```

A mean, as SQL's `AVG` or a `mean` elsewhere, is no operator of the
prelude's yet, since the mean of integers isn't an integer; the error says
to divide `sum` by `count`, converting with `to_approximate`:

```trendy,error
var harvests := relation { { crop: "wheat", tonnes: 950 }, { crop: "tea", tonnes: 120 } };
var mean := avg{r: harvests, of: tonnes};

operator main{} [];
```

A local variable is in scope in the block it is declared in, from its
declaration to the block's end, so one declared in a branch of an `if`
statement is unknown after it. To use it after the `if`, declare it
before, in the block that holds both:

```trendy,error
operator report{n: integer} [
    if n > 0 then [
        var note := "positive";
    ];
    call debug_value{v: note};
];

operator main{} [];
```

In the `where` of a load into a relation without `numbered`, a name that
is no misspelling of one in scope may be meant as each element's
position, which only `numbered` names, as an attribute the relation then
has as well:

```trendy,error
operator main{} [
    var texts := array ["river", "Nile", "Niger"];
    var rivers: relation { river: text };
    load rivers from texts as river where n > 1;
];
```

An operator the interface of a unit of the program declares, which the
section it is called in doesn't use, gets a fix that names the unit in
that section's `uses`, as an unknown type does (A0003). For the unit
`lakes/rivers.trendy`:

```trendy,unit lakes.rivers
interface

operator longest{}: text;

implementation

operator longest{}: text [ "Nile" ];
```

```trendy,error
operator main{} [
    call debug_value{v: longest{}};
];
```

So does one of a unit that comes with the compiler, as `load_text_file`
is `trendy.files`'s:

```trendy,error
operator main{} [
    var lines: array text;
    call load_text_file{path: "rivers.txt", out lines: lines};
];
```

A unit a `uses` names is one of the program's: main's, those its units
use, and those that come with the compiler, as the catalog's constraint
`known_units` says. Each is named by its path from the directory of
`main`'s file, so the error says which file it would be, and a
misspelling of one is fixed to it. For the unit `lakes/depths.trendy`:

```trendy,unit lakes.depths
interface

heading lake := { name: text, depth: integer };
```

```trendy,error
uses { lakes.depth };

operator main{} [];
```

```trendy
uses { lakes.depths };

operator main{} [];
```

Use a defined name:

```trendy
var count := 1;
var harvests := relation { { crop: "wheat", tonnes: 950 }, { crop: "tea", tonnes: 120 } };
var crops := count{r: harvests};
var rainfall := array [1200, 950, 220];
var months := length{a: rainfall};
var one := array [1];
var slope := sin{of: 5e-1} / cos{of: 5e-1};
var circumference := 2e0 * pi{} * 1.5e0;
var mean := to_approximate{from: sum{r: harvests, of: tonnes}} / to_approximate{from: count{r: harvests}};

operator report{n: integer} [
    var note := "not positive";
    if n > 0 then [
        note := "positive";
    ];
    call debug_value{v: note};
];

operator main{} [
    call debug_value{v: count};
    var texts := array ["river", "Nile", "Niger"];
    var rivers: relation { river: text, n: integer };
    load rivers from texts as river numbered n where n > 1;
];
```
