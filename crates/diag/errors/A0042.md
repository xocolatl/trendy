# A0042: `per` without a relation

A parameter `p: type per r` takes an argument evaluated for each tuple of
the argument for `r`, with that tuple's attributes in scope, as in `where`,
and inside the operator, `p` is an attribute of `r`'s tuples. So `r` must
be another parameter of the operator, of type `any relation`, and not a
`per` parameter itself. The operator sees `r`'s tuples with the `per`
parameters' values beside their own attributes, which are wrapped in one
it can't name, so that they stay distinct but can't clash with those it
names; a relation of a known heading needs none of that, since the
operator can name its attributes itself. Only an operator's parameters
have `per`.

```trendy,error
operator values{rows: any relation, of: T per r}: relation { v: T }
    types { T: any type }
[
    rows{of} rename {of as v}
];

operator main{} [];
```

```trendy,error
operator total{r: relation { amount: integer }, of: integer per r} [];

operator main{} [];
```

Name an `any relation` parameter after `per`:

```trendy
operator values{r: any relation, of: T per r}: relation { v: T }
    types { T: any type }
[
    r{of} rename {of as v}
];

operator main{} [];
```
