# A0022: operator applied to the wrong type

The arithmetic operators `+`, `-` and `*` take two integers or two
approximate numbers. The others are specific to one type:

- `/` divides approximate numbers;
- `div` divides integers, truncating toward zero;
- `mod` is the remainder of `div`, of integers;
- `||` concatenates text;
- `<`, `<=`, `>` and `>=` order booleans, integers, approximate numbers,
  text, and the values of a type of the program's own with an order, by
  it, and relations as sets: `<=` is subset, and `<` proper subset.
  Tuples, arrays, and the values of a type without an order, have no
  order; they only have `=` and `<>`. The help on a type without one says
  how to give it one, `order [asc …]` in its braces.
- `a[i]` takes an array: only its elements have positions. A relation's
  tuples have no order (TTM RM Proscription 2), so a relation has none,
  and a tuple's attributes are named, not numbered: `t["name"]`, as other
  languages index a dictionary, is fixed to `t.name`.
- `join`, `times` and `compose` take relations, or tuples, but not both: a
  tuple among relations is fixed to a relation of it, `relation { t }`.
  `matching` and `not matching` take relations only, and so do `union`,
  `d_union`, `xunion`, `intersect`, `minus` and `i_minus`, of one heading; Tutorial D's tuple union is
  `join`, and `union` of tuples is fixed to it.
- `where` takes a relation; a tuple satisfies a condition or doesn't, so
  the condition itself is that boolean.
- `tuple from` and `value from` take relations, and `value from` one of
  one attribute. Of a tuple, `tuple from t` is fixed to `t`, and
  `value from t` to `t.a`, its only attribute's value.
- `!!`, `group` and `ungroup` take relations, and `ungroup`
  relation-valued attributes of them; `unwrap` takes tuple-valued
  attributes of a tuple or relation.
- projections, `remove`, `rename`, `extend` and `replace` take a tuple or
  relation, and `replace` and `update` also a value of a type of the
  program's own, whose components they give new values. Its type's
  components are the ones it declares, so none is projected away, added,
  removed or renamed.
- a `for` loop goes through an array's elements. A relation's tuples have
  no order to go through them in, so a load puts them in an array first.
- a load orders by attributes of types with `<`: booleans, integers,
  approximate numbers, text, and types of the program's own with an
  order. Relations are ordered only as sets, which doesn't put every two
  in an order, so they can't be ordered by. So does a type's order, by its
  components.

Values never convert to another type implicitly, so `/` can't divide integers,
`div` can't divide approximate numbers, and `+` can't concatenate text. Where
another operator does what was meant, the fix replaces the operator with it:
`div` for `/` on integers, `/` for `div` on approximate numbers, `||` for `+`
on text, and `or` for `||` on booleans. A value of another type converts
explicitly, which is the other fix: `/` of an integer by an approximate
number converts the integer with `to_approximate`, and `||` of a number,
or of a type parameter's value, converts it with `to_text`:

```trendy,error
operator density{people: integer, km2: approximate} [
    call debug_value{v: people / km2};
];

operator main{} [];
```

```trendy,error
operator label{people: integer} [
    call debug_value{v: people || " people"};
];

operator main{} [];
```

```trendy,error
var half := 7 / 2;

operator main{} [];
```

```trendy,error
var half := 7e0 div 2e0;

operator main{} [];
```

```trendy,error
var greeting := "hello, " + "world";

operator main{} [];
```

```trendy,error
var city := tuple { name: "Lagos", people: 15400000 };
var name := city["name"];

operator main{} [];
```

A type parameter's values take only what every type it can be has: `=`
and `<>`, and what its kind requires, `<` of `any ordered` and `+` and `*`
of `any numeric`. The help names the kind whose types have the operator:

```trendy,error
operator total{a: T, b: T}: T types { T: any type } [
    a + b
];

operator main{} [];
```

An operator is called by its name, with its arguments named in braces,
none of them before it as a method's receiver, so `.` after a value takes
an attribute of a tuple, never calls an operator. Called as a method, with
braces or without, an operator of one parameter is fixed to a call of it:

```trendy,error
var dishes := relation { { dish: "ramen" }, { dish: "pozole" } };
var how_many := dishes.count{};

operator main{} [];
```

Use the operator for the operands' type, or write the operands as the other
type, declare a type parameter of a kind that has the operator, and call
an operator by its name:

```trendy
operator total{a: T, b: T}: T types { T: any numeric } [
    a + b
];

var truncated := 7 div 2;
var half := 7e0 / 2e0;
var greeting := "hello, " || "world";
var city := tuple { name: "Lagos", people: 15400000 };
var name := city.name;
var dishes := relation { { dish: "ramen" }, { dish: "pozole" } };
var how_many := count{r: dishes};

operator main{} [];
```
