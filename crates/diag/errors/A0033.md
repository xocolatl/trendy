# A0033: an assignment that changes nothing

An assignment gives a variable a new value, and an `update`'s or a
`replace`'s assignments give attributes new values. A variable or an
attribute that isn't given a new value keeps its own, so giving it its own
value changes nothing, and neither does inserting or deleting no tuples:

- `v := v;`, or a value that is `v`'s own once simplified, such as
  `n := n + 0;`;
- `insert r relation {};`, and the same with `d_insert` or `i_delete`;
- a `delete` or an `update` whose condition is known when compiling to be
  false whatever the tuple, such as `false` or `1 = 2`;
- `insert r r;`, whose tuples are all there already, and `d_insert r r;`,
  which fails if `r` has a tuple, and otherwise changes nothing, when it
  is `r`'s one change: in an `assign` block with changes that remove
  tuples, it adds them back;
- `a := a` in an `update`'s or a `replace`'s list.

The fix deletes what changes nothing: the statement, the assignment from
its list, or, when an `update` or a `replace` gives each attribute its own
value, all of it:

```trendy,error
var poets := relation { { name: "Ada", born: 1815 } };
var visits := 0;

operator main{} [
    visits := visits;
    insert poets relation {};
    d_insert poets poets;
    delete poets where false;
    update poets { name := name, born := born + 1 };
];
```

```trendy,error
var poets := relation { { name: "Ada", born: 1815 } };
var same := poets replace { born := born };

operator main{} [];
```

```trendy
var poets := relation { { name: "Ada", born: 1815 } };
var visits := 0;
var older := poets replace { born := born + 1 };

operator main{} [
    visits := visits + 1;
    update poets { born := born + 1 };
];
```
