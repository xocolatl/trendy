# A0032: a change of every tuple that doesn't say so

A change of every tuple of the relation variable `r` is written so that it
says so: `r := relation {};` deletes them all, and `update r { … };`,
without `where`, updates them all. Changes that select every tuple
another way are errors, and the fix writes them so:

- a `delete` or an `update` whose condition is known when compiling to be
  true whatever the tuple, such as `true` or `1 = 1`;
- `i_delete r r;`, which names every tuple of `r`.

A `delete` needs a condition so that every tuple isn't deleted by accident
(P0023); one that is always true would get around that.

```trendy,error
var poets := relation { { name: "Ada", born: 1815 } };

operator main{} [
    update poets { born := born + 1 } where 1 = 1;
    delete poets where true;
    i_delete poets poets;
];
```

In an `assign` block, the assignment of a whole new value can't combine
with other changes to the variable (R0009), so a deletion of every tuple
with an `insert` is the assignment of what is inserted:

```trendy,error
var rooms := relation { { room: 1, guest: "Kenji" } } key { room };
var arrivals := relation { { room: 2, guest: "Amara" } };

operator main{} [
    assign {
        delete rooms where true;
        insert rooms arrivals;
    };
];
```

```trendy
var poets := relation { { name: "Ada", born: 1815 } };
var rooms := relation { { room: 1, guest: "Kenji" } } key { room };
var arrivals := relation { { room: 2, guest: "Amara" } };

operator main{} [
    update poets { born := born + 1 };
    poets := relation {};
    rooms := arrivals;
];
```
