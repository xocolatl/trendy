# A0032: `delete` or `update` with a condition known when compiling

`delete r where p;` and `update r { … } where p;` change the tuples of the
relation variable `r` for which the condition `p` is true. A condition
known when compiling to be the same whatever the tuple, such as `true`,
`1 = 1` or `false`, selects every tuple or none, which is written without
it:

- a `delete` of every tuple is the assignment of the empty relation,
  `r := relation {};`, which says so, as `delete` needs a condition so that
  every tuple isn't deleted by accident (P0023);
- an `update` of every tuple has no `where`: `update r { … };`;
- a change of no tuple changes nothing, so it goes.

The fixes write each:

```trendy,error
var poets := relation { { name: "Ada", born: 1815 } };

operator main{} [
    update poets { born := born + 1 } where 1 = 1;
    delete poets where false;
    delete poets where true;
];
```

In an `assign` block, the assignment of a whole new value can't combine
with other changes to the variable (R0009), so a `delete` of every tuple
with an `insert` is the assignment of what is inserted:

```trendy,error
var rooms := relation { { room: 1, guest: "Kenji" } } key { room };
var arrivals := relation { { room: 2, guest: "Amara" } };

operator main{} [
    assign {
        delete rooms where true;
        insert rooms arrivals;
    };
];
```

```trendy
var poets := relation { { name: "Ada", born: 1815 } };
var rooms := relation { { room: 1, guest: "Kenji" } } key { room };
var arrivals := relation { { room: 2, guest: "Amara" } };

operator main{} [
    update poets { born := born + 1 };
    poets := relation {};
    rooms := arrivals;
];
```
