# R0022: a program's own warning

`warn e;` warns with the error `e`, a value of one of the subtypes of the
prelude's type `error`, and the program carries on. The innermost
transaction with `collecting` running collects it, adding it, `failed`
false, to the variable `collecting` names, a `relation
transaction_collection`, whatever operator the warning is in; a
transaction without `collecting` leaves it to the one around it. With
none running, nothing collects it, and the program writes its message to
stderr, as its `message` gives it, and where it warned, as in
`warning[R0022]: Accra has 5 sacks left`, then carries on. The compiler
never computes an update operator, so this is reported only when the
program runs.

A warning a transaction collects is written nowhere, unless the program
writes it: its `message` gives its text, as for a failure's error, and
`found where not failed` the warnings a transaction collected in `found`.

```trendy
type running_low is error { { city: text, sacks: integer } };

operator message{error: running_low}: text [
    error.city || " has " || to_text{from: error.sacks} || " sacks left"
];

operator main{} [
    var found: relation transaction_collection;
    transaction collecting found [
        warn running_low{city: "Accra", sacks: 5};
    ];
    var warnings := found where not failed;
    call debug_value{v: (warnings extend { message := message{error: error} }){message}};
];
```

Only an update operator warns, as it runs: a read-only operator or a
value block computes a value, which the compiler may compute before the
program runs, when a warning would be lost (A0035).
