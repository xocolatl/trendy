# P0050: an exception handler

trendy has no `try` and no `catch`: nothing in an expression, or around a
statement, takes a failure. A transaction does, and undoes its block's
statements, all of them, when one fails. With `collecting e`, it adds the
failure's error to the variable `e`, a relation of errors, declared
before it, which the statements after it can test, rather than letting
it stop the program:

```trendy,error
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
};

operator main{} [
    try [
        update stock { sacks := sacks div 0 };
    ] catch [
        call debug_value{v: "no sacks moved"};
    ];
];
```

Written as trendy writes it, with an error of its own the program fails
with, which the transaction collects:

```trendy
var stock: relation { granary: text, sacks: integer } := relation {
    { granary: "Accra", sacks: 40 },
};

operator take{sacks: integer} [
    if sacks > 40 then [
        fail failure{message: "Accra has too few sacks"};
    ];
    update stock { sacks := sacks - 10 };
];

operator main{} [
    var found: relation { error: error };
    transaction collecting found [
        call take{sacks: 50};
    ];
    if not is_empty{r: found} then [
        call debug_value{v: "no sacks moved"};
    ];
];
```
