# R0004: tuples disagree

Two tuples join when they agree on every attribute they have in common:
the result has the attributes of both. When a common attribute has
different values in the two, there is no tuple that could be the result.
Relations don't have this problem, since a join of relations whose tuples
don't match just has no tuples; a join of tuples has to have one.

`times` never fails, since its operands have no attribute in common, and
`compose` fails just as `join` does, before it removes the common
attributes.

When the tuples are known while compiling, the mismatch is reported there:

```trendy,error
var ada := tuple { name: "Ada", born: 1815 };
var place := tuple { name: "Ada Lovelace", city: "London" };
var both := ada join place;

operator main{} [];
```

When a tuple is known only when the program runs, the program stops at
the join instead, writing the attribute and its two values to stderr, as
in ``error[R0004]: the tuples disagree on `name`, so they have no join:
`name` is "Ada" in one and "Ada Lovelace" in the other``, and exiting with
status 1, unless a transaction takes its error, a `tuple_mismatch {
attribute, first, second }`.

If the two attributes mean different things, rename one so that they
aren't matched; if only some pairs of tuples match, join relations of
them, which keeps just the tuples that do:

```trendy
var ada := tuple { name: "Ada", born: 1815 };
var place := tuple { name: "Ada Lovelace", city: "London" };
var both := ada times place rename {name as full_name};
var joined := relation { ada } join relation { place };

operator main{} [];
```
