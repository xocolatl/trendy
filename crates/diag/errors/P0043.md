# P0043: a supertype named as another language names a base type

A type declared `is` a union type is one of its subtypes: every value of
it is a value of the union type, which has no values of its own (*Type
Inheritance and Relational Theory*, chapter 12). The union type is named
after `is`, between the type's name and its braces:

```trendy
type plane_figure union;

type ellipse is plane_figure { { a: approximate, b: approximate } };
type polygon is plane_figure { { corners: integer } };

operator main{} [];
```

Java's `extends` and Kotlin's and C#'s `:` are fixed to `is`:

```trendy,error
type plane_figure union;

type ellipse extends plane_figure { { a: approximate, b: approximate } };
type polygon: plane_figure { { corners: integer } };

operator main{} [];
```

Tutorial D writes the supertype and the possible representation in braces
together, `TYPE ELLIPSE IS { PLANE_FIGURE POSSREP ( A LENGTH, … ) }`.
trendy names the supertype alone after `is`, and the representation
follows in the type's braces, written as everywhere else, so there is no
fix:

```trendy,error
type plane_figure union;

type ellipse is { plane_figure possrep { a: approximate, b: approximate } };

operator main{} [];
```
