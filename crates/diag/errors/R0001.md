# R0001: arithmetic overflow

An arithmetic operator whose result is out of its type's range has no
result. It never wraps around, saturates, or becomes an infinity.

- Integers are 64-bit signed, from -9223372036854775808 to
  9223372036854775807. `-9223372036854775808 div -1` overflows, because the
  quotient would be 9223372036854775808, and so does negating the smallest
  integer.
- Rationals are finite, up to about 1.8e308 in magnitude. A result beyond
  that overflows. A result too small to represent is rounded, toward zero if
  need be, as IEEE 754 arithmetic rounds; that is not an error.

When the operands are known while compiling, the overflow is reported
there:

```trendy,error
var big := 9223372036854775807 + 1;

operator main{} [];
```

```trendy,error
var huge := 1e300 * 1e10;

operator main{} [];
```

When an operand is known only when the program runs, the program stops at
the overflowing operator instead, writing `error[R0001]: integer overflow`
or `error[R0001]: rational overflow` to stderr and exiting with status 1.

Keep the values in range, or rearrange the computation so that no
intermediate result leaves it:

```trendy
var big := 9223372036854775807 - 1 + 1;
var huge := 1e300 / 1e10;

operator main{} [];
```
